Inspect lock syntax, resolve compiler references and check exact dispositions.

inspect reads repository source without compiling it. It retains candidates,
inferred roles, hold intervals, unknowns and unscanned inputs. Unit Mutex/RwLock
payloads are candidates, never proof that data or poison protocols can be removed.

resolve compiles the staged Rust workspace through the existing Guard source
seat, Cargo lease, locked package preparation and execution environment. It runs
Clippy offline for the workspace, explicitly selecting rustc's host triple
and all target kinds, with
default workspace features and no dependency linting. --all-features selects
all workspace features instead. Each selection is one compiled combination,
not every combination or transitive optional branch. Stage the intended inputs first;
unstaged edits are not compiled. Normal compiler prerequisites still apply.
It prepares the Rust action and its declared prerequisite probes, then compiles
the workspace. Normal compilation may execute build scripts and proc macros;
application tests and Windtun suites are not run. No Guard action is activated.

The current compiler collector covers the five std::fs::File locking methods:
lock, lock_shared, try_lock, try_lock_shared and unlock. It recognizes their
resolved references through aliases, function values and macro expansion.
Existing root Clippy settings are retained in an isolated configuration; the
collector's methods cannot be suppressed by source allow attributes.

--json identifies the actual collector executable and its version/commit, and
binds the original staged and effective source trees, locked resolution,
execution digest, tool identities, actual rustc/Clippy versions, configuration
digest and command. Findings retain package, target and complete compiler spans,
including expansion chains. Environment values are not emitted. Cargo artifacts
include dependencies and may be cached; they are not proof that dependency
methods were linted. Diagnostics may repeat across lib/test compilation units.

Exit zero means collection succeeded in that exact scope, even when references
were found. Compilation failure, malformed/incomplete machine output and
unavailable prerequisites refuse with exit 2. A report is not an admission
judgment: roles, cleanup, hold intervals and precise dispositions need review.
Other locking APIs, languages, target triples, feature combinations and
unselected cfg branches remain outside this compiler scope. This command creates no Guard
proof and does not turn an incomplete global inventory into a pass.

Each resolved finding includes a reference. A bound reference has a digest and
workspace-relative tracked regular file digests. Its identity includes the actual host, feature
selection, rustc/Clippy versions, package, target, complete normalized spans and
expansion chain, Cargo.lock and the relevant Cargo manifests and source files.
The original compiler fields are retained. Relocating an identical workspace
does not change the identity. Lib/test observations may share one source
reference; this does not identify each diagnostic's cfg. External, generated or
unreadable sources that cannot be bound within the staged workspace remain
unknown and cannot receive a successful disposition check.

check compiles every declared combination once through the same source seat,
Cargo lease and prepared environment. Declare [guard.lock] in plumb.toml with
one explicit target triple matching rustc's host and a nonempty, unique features
list containing "default", "all-features", or both. No other combinations or
targets are implicitly covered. The declaration is for this explicit command;
its presence alone does not activate Guard.

For every distinct reference in those reports, add one [[guard.lock.review]]
with its reference digest, role, protocol, hold, release, verification and
nonempty evidence table. Roles are carrier, interoperability or compatibility:
they record human dispositions, not authenticated carrier authority or a proof
of business correctness. Data/stdio locks and unit Mutex payloads are not
classified as these five native File methods by spelling.

evidence maps exact workspace-relative tracked regular file paths to lowercase SHA-256
digests. Include the files supporting the protocol and hold/release review.
The reference already binds its own source and Cargo inputs. No globs, directory
grants, absolute or redirected paths substitute for exact evidence. All review
fields are required and unknown fields refuse. For example:

[guard.lock]
target = "x86_64-unknown-linux-gnu"
features = ["default", "all-features"]

[[guard.lock.review]]
reference = "<digest from the matching resolved combination>"
role = "interoperability"
protocol = "native interoperability fixture and its owning protocol"
hold = "reviewed acquisition and complete handle interval"
release = "reviewed cleanup and fault behavior"
verification = "specific regression assertions supporting this review"
[guard.lock.review.evidence]
"tests/protocol.rs" = "<SHA-256 of the staged evidence file>"

Run plumb lock check . --json after staging both declaration and intended source.
Missing, duplicate, stale or surplus reviews, changed evidence, unbound sources
and target/feature disagreement refuse with exit 2 and no complete stdout report.
Success reports consistent=true, the human declarations and complete collected
reports, with guard=false. It proves source-bound review consistency only:
Ectropy grant/ban policy, carrier authority, actual safety and unexecuted scopes
remain separate obligations. Setting enforce=true explicitly opts the declaration
into ordinary Guard, which requires actual Ectropy participation and records a
separate guard/lock action. See plumb guard --help. The explicit check command
still creates no Guard proof and never substitutes for that activation.
