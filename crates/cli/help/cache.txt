Use `plumb cache run` for a disposable source experiment with retained evidence.
Use `plumb cache transport` for verified Guard compilation material.

Declare the compilation material a caller may transport between Guard jobs.

The JSON document owns one atomic Zstandard parcel path, primary key, restore
prefix, artifact name, immutable image identity and populated state. Transport
only that parcel; disable outer archive compression. It excludes Git
administration, source worktrees, live leases, Guard action/descriptor proofs and
delivery authority. Run --restore before Guard and --save after a successful Guard. Publish only
when the resulting report is populated. Empty material never claims a cache key. Missing or rejected material causes recompilation.

PLUMB_GUARD_CONTAINER declares the exact current Linux Docker container ID. Plumb
reads its immutable image ID through the local Docker socket and verifies its
hostname against the current container. The image identity joins the executed
Guard world. Keep this setting on both the transport command and Guard. Neither a
mutable image tag nor a caller-supplied image digest replaces that observation.
Without this supported container context, the report declares compiler-cache
transport only; it does not opt local Cargo artifacts into cross-job reuse.

Native debug/release Cargo content is sealed against its actual bytes and source
inputs. A fresh checkout restores timestamps only for identical verified inputs;
changed inputs receive fresh timestamps. Pending, partial, mismatched or future
snapshots cannot restore old freshness. Failed attempts remain unsealed. Cargo
and source ownership leases remain local, and every actual Guard check and
source/package/tool judgment remains required. A cache is never a verdict.
Per-target output directories, such as the explicit host triple used by
guard/lock, stay local: they neither block nor join the native snapshot. When
--save does not pack native Cargo content, a material.native diagnostic event
names the reason.

A parcel that carries compilation material also carries the guard/test timing
history from PLUMB_HOME state when present. Restore adds only missing timing
records and never replaces existing ones; a failed timing restore is reported
and leaves compilation material in place. Timings only advise test scheduling.
Parcels without timing history still restore.

With --save, Plumb itself decides whether to pack native Cargo content. A run
on a follow branch packs only compiler material, because a follow changes the
first-party package world and no later job can restore the native layer. A
follow branch is a pull request whose GITHUB_HEAD_REF begins with auto/, or a
run whose GITHUB_REF is refs/heads/auto/. The skip is reported on stderr and as
a material.skip diagnostic event, and the receipt still reports cargo false.
PLUMB_GUARD_NATIVE=keep or skip overrides the rule; auto, the default, applies it.
The caller only passes the branch variables it already provides.

With --restore --fetch, an unavailable native snapshot may be seeded from a
successful organization Guard artifact whose exact head tree is in the locally
fetched default branch history, or whose originating run belongs to the same
pull request as the current job. Lookup is bounded: metadata and artifact
download share one wall-clock budget, 60 seconds by default. Artifact listing
scans at most 25 pages of 20 artifacts by default, newest first, and only
guard-material-v1- names are candidates. Scanning stops at a short page, that
page cap, or the remaining budget. PLUMB_GUARD_RESTORE_BUDGET overrides the
budget with a positive number of seconds; PLUMB_GUARD_RESTORE_PAGES overrides
the page cap with a positive page count. The rules live in Plumb; a caller may
only override those bounds. Lookup requires GH_TOKEN or GITHUB_TOKEN with
repository Actions read access. The credential is isolated from repository
execution and is never forwarded to artifact storage. The artifact digest,
parcel identity and native content are independently checked. Metadata,
download, budget expiry or cache rejection falls back to ordinary compilation
and does not keep partial material. This fetch supplies compilation material;
current Guard checks still execute.

For diagnostic export, --diagnostic NEW_FILE on transport writes bounded
plumb.guard-diagnostic/v1 JSON-lines independently of the material receipt.
Use a new file outside the guarded worktree for each invocation. See plumb guard
--help for timing, resource, completeness and proof-separation semantics.
