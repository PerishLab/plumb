Declare the compilation material a caller may transport between Guard jobs.

The JSON document owns one atomic Zstandard parcel path, primary key, restore
prefix, artifact name, immutable image identity and populated state. Transport
only that parcel; disable outer archive compression. It excludes Git
administration, source worktrees, live leases, Guard action/descriptor proofs and
delivery authority. Run --restore before Guard and --save after a successful Guard. Publish only
when the resulting report is populated. Empty material never claims a cache key. Missing or rejected material causes recompilation.

PLUMB_GUARD_CONTAINER declares the exact current Linux Docker container ID. Plumb
reads its immutable image ID through the local Docker socket and verifies its
hostname against the current container. The image identity joins the executed
Guard world. Keep this setting on both the transport command and Guard. Neither a
mutable image tag nor a caller-supplied image digest replaces that observation.
Without this supported container context, the report declares compiler-cache
transport only; it does not opt local Cargo artifacts into cross-job reuse.

Native debug/release Cargo content is sealed against its actual bytes and source
inputs. A fresh checkout restores timestamps only for identical verified inputs;
changed inputs receive fresh timestamps. Pending, partial, mismatched or future
snapshots cannot restore old freshness. Failed attempts remain unsealed. Cargo
and source ownership leases remain local, and every actual Guard check and
source/package/tool judgment remains required. A cache is never a verdict.

With --restore --fetch, an unavailable native snapshot may be seeded from a
successful organization Guard artifact whose exact head tree is in the locally
fetched default branch history. Lookup is bounded and requires GH_TOKEN or
GITHUB_TOKEN with repository Actions read access. The credential is isolated
from repository execution and is never forwarded to artifact storage. The
artifact digest, parcel identity and native content are independently checked.
Metadata, download or cache rejection falls back to ordinary compilation.
This fetch supplies compilation material; current Guard checks still execute.

For diagnostic export, --diagnostic NEW_FILE on transport writes bounded
plumb.guard-diagnostic/v1 JSON-lines independently of the material receipt.
Use a new file outside the guarded worktree for each invocation. See plumb guard
--help for timing, resource, completeness and proof-separation semantics.
