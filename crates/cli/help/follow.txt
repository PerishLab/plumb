Run or resume the registered Auto follow operation for this GitHub repository.

A current main is a no-op with no new Issue or pull. A bounded dependency delta
creates or reuses one automation-owned Auto Issue and auto/<number> branch.
Only registered first-party manifests and locks may change. The operation proves
local Guard, publishes an exact candidate, waits within a finite bound for the
required organization Guard, and revalidates before the ordinary squash merge.
Closure reads back the merge commit and successful Guard run before accepting
and closing the Issue.

An already-published exact candidate is not pushed again. Multiple matching
Guard runs are accepted only when every check and linked organization workflow
on that head has completed successfully; pending, failed, foreign or unreadable
evidence still prevents merging.

If main already holds the Auto's own exact published pull and latest-stable
resolution leaves no registered delta, follow records a writer-qualified
absorption receipt, closes the pull unmerged, retires its branch by lease and
accepts the Issue, reading back each step without a new merge or Guard.
Rerunning an interrupted settlement resumes from that receipt.

State and one local repository lease live under PLUMB_HOME. A disposable clone
and empty home recover from the registered GitHub Issue, exact publication
intent, branch and pull. New local proof and delivery preparation replace old
path-bound plans. Publication intent is read back before pushing; provider
facts decide whether an interrupted write completed. Stage labels grant no
recovery authority. Provider writes are read back before resuming; a duplicate relationship, needs label, open child or
blocker, foreign branch movement, permissions refusal or failing Guard stops
the operation. A stopped operation records the available Issue, pull and failure
evidence. Repair the blocker and rerun this same command.

Closing the Auto Issue and pull by hand stops follow on purpose; it never
retires them itself. When that close is final, --retire clears the seat: it
refuses unless the recorded Issue and pull are both closed, the pull is not
merged, no absorption or no-op receipt is recorded and no other follow holds
the lease. It then removes the owned auto/<number> branch by exact lease and its
worktree, clears the seat and prints what it retired, so the next plain run
opens a fresh Auto from current main.

Use --recover AUTO_ISSUE for a recorded Auto whose merged pull head superseded
its local candidate. The Issue must already be completed by the same writer
with exact closure evidence. Recovery requires the complete same-base,
same-tree publication chain through the exact merged head, the original
candidate's recorded proof, a successful historical organization Guard on the
final head, and an exact squash contained by origin/main. It also requires the
remote branch to be absent and the owned worktree to be clean at a known head.

Recovery retains the original state and observations in recovered-<number>.json
under the repository's follow state directory. It keeps the original worktree
and local branch. It clears only the active seat, so a plain follow can start
again with fresh Guard evidence. Repeating recovery reports the prior receipt.
Recovery refuses inconsistent or missing evidence. It makes no GitHub writes.

Before opening a new Auto, follow scans origin for leftover auto/<number>
branches. One is waived only when its Issue is closed, exactly one merged pull
and no open pull has that head, no running follow or local worktree holds it,
origin/main..auto/<number> has no merge commit and every git cherry line against
origin/main is marked -. Any other leftover, or one it cannot judge, stops
before an Issue is created; follow never deletes it. The waiver covers only the
leftover-branch signal.

Only the Auto Issue's author, its operation writer, runs or settles it. Any
other identity refuses before its first write, naming the writer and itself.
Another identity's marker comment refuses every run until it is resolved,
unless the writer posted the identical comment itself; see plumb cookbook
follow.foreign-writer.

GitHub access uses the active credential's Runseal client. Set GITHUB_TOKEN_FILE
for explicit token custody or use the GitHub token carried by your Runseal profile.
Auto has no Concord Member and does not repair business source or perform releases.
