Judge this repository against the skeleton and report every finding.

--json includes shape.topology (plumb.topology/v3): package identities and
qualified sources, workspace membership, resolved features, declared edges,
dependency kinds, target conditions, optionality, requirements and aliases.
Its input digest binds the declaration, lock, Cargo metadata, origin, staged
Git tree and Cargo version. This observation is freshly captured on every run.
It is not a reusable Guard proof. Cargo metadata runs frozen with all features;
it does not fetch packages or rewrite the lock. Incomplete or unsupported
sources, resolution, parsing and resource exhaustion remain unknown.

Strict roots with unresolved crates.io declarations additionally capture a
conservative declaration closure from the canonical sparse index. This reads
index records, never executes build scripts, and changes neither manifests nor
locks. Candidate nodes have no selected version: candidates list every matching
published version, checksum and yanked status, including withdrawn versions.
Their edges retain the parent versions, dependency kinds, features and targets.
All optional and platform branches participate. A fully read index with no
matching version is an empty candidate set; an absent locked version remains
unknown. This superset can refuse paths
that no single Cargo resolution would select; it is not a resolved graph.

closure records the exact index digests, counts, completion and input digest.
The context names declaration-candidates and the topology input binds that
material. Canonical responses are stored as integrity-checked, content-addressed
snapshots below Plumb's managed data home. Each capture has bounded time, bytes,
versions, ranges and edges. Missing, partial, corrupt, unsupported or exhausted
material remains unknown. Source replacement, patches and registry overrides
are not qualified by this mechanism. Ordinary repositories do not use it.

Cycles project PerishLab registry packages across versions by package identity,
retaining each exact package and source in the witness. Ordinary repositories
observe cycles without enforcing a general domain order. Exact-package dev
self-tests appear separately in tests; they do not excuse a root violation.

A repository opts into strict library roots with this plumb.toml declaration:

  [dependency]
  root = true

deps.root-library-closed then refuses binary workspace targets and every path
from a workspace library to another domain package, including another library
in the same repository. Third-party intermediates do not hide the path.
Independent-root repositories do not require a crate named after the repository.
Normal, build, optional, platform and the root's own dev dependencies participate.
A dependency package's own dev dependencies do not propagate to its consumer;
those edges remain visible with propagated=false. Unknown relevant branches
prevent a clean root verdict while preserving any known violations.

One public capability may require several technical workspace crates. Declare
their exact package names explicitly, for example:

  [dependency.groups]
  lock = ["radicula-lock", "radicula-lock-macros"]

When groups are present, every workspace library belongs to exactly one nonempty
named group. Missing, duplicate, overlapping, unknown or ambiguous membership
prevents a clean verdict. Only direct edges between members of the same group
are admitted. All actual edges remain visible; a third-party intermediary,
another capability or a published domain package is not an internal exemption.
Group cycles refuse judgment. With no groups, each library retains the original
independent-root contract. Group declarations create no package or release.

There is no root=false exemption. CLI execution outside the library graph does
not create a library dependency. Node root closures are not yet supported and
an opted-in repository carrying package.json reports unknown.
