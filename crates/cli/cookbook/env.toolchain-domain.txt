# env.toolchain-domain

## Trigger

A tool the repository uses does not run, or reports a version other than the
domain version Plumb carries.

## Solution

Bring the environment onto the domain versions; do not declare a version in
the repository. `plumb metadata --json` prints them.

- Rust: `rustup default <rust.version>`. The repository carries no
  `rust-toolchain.toml`, so the default is what every cargo call uses.
- Node: install `<node.version>` with your version manager and make it the
  active Node.
- pnpm: `npm install --global pnpm@<pnpm.version>` into that Node. Do not use
  corepack; if `pnpm` resolves into corepack, run `corepack disable` first.
- CI: run in `ghcr.io/perishlab/images:stable`, which carries the domain
  versions.

Install or replace a tool while no Guard is running on the machine; Guard
refuses a tool that changes during a run.

## Evidence

A repository that declared its own versions could only be checked against
itself, and every version move had to switch every repository at once.

## EXIT

Remove this entry when Plumb installs the domain tools itself, or when the toolchain-domain law retires.
