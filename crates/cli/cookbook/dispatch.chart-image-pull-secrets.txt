# dispatch.chart-image-pull-secrets

## Trigger

A Helm chart under `charts/*` declares a Kubernetes workload (`Deployment`,
`StatefulSet`, `Job`, `CronJob`, or `DaemonSet`) with a `values.yaml`, but
either `values.yaml` omits top-level `imagePullSecrets:` or a workload template
omits `imagePullSecrets:` from its pod spec.

## Solution

Declare top-level `imagePullSecrets: []` in `charts/<name>/values.yaml` so
Public-first anonymous pulls remain the default, and wire optional
`imagePullSecrets` into every workload pod spec with `nindent 8`:

    {{- with .Values.imagePullSecrets }}
    imagePullSecrets:
      {{- toYaml . | nindent 8 }}
    {{- end }}

## Evidence

Omitting `imagePullSecrets` from product charts forces out-of-band
ServiceAccount patches whenever a cluster pulls from a private repository,
authenticated mirror, or rate-limited registry. Exposing an empty `[]` default
preserves Public-first pulls while keeping registry credentials declarative.

## EXIT

Remove this entry if PerishLab charts adopt a different standard mechanism for optional registry pull credentials.
