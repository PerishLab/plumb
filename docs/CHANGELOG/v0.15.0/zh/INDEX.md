# plumb v0.15.0

## 磁盘上只留一个版本

`manage.sh install` 与 `update` 现在只留下一个版本。新二进制链接完成并能答出
`--version` 之后，安装根目录下的其余版本目录一律删除。

带版本号的安装根目录看起来是为回滚准备的，但从来没有任何代码读它：
`install --version <旧版本>` 的第一个动作就是删掉那个目录再重新下载一遍。
一天之内攒了 11 个版本、46MB，而没有任何一条路径会用到它们中的任何一个。

清理会报出删掉了什么，不静默执行。

## `plumb changelog`

新命令读取 `docs/CHANGELOG/v<version>/{en,zh}/{INDEX.md,MIGRATION.md}`，四份
文件缺失或为空即拒绝。版本来自 `--version`；不传时取仓库自己声明的版本。

英文与中文是**下限，不是集合**。仓库可以加更多语言，但不能少于这两种就发
stable。

## stable 发布的变更日志门控

`release-stable.yml` 在第一个不可逆步骤之前调用该命令。强制点在这里——
`plumb doctor` **不检查**变更日志，所以 bump 版本号永远不会让工作树变红。
变更日志是**发布**的属性，不是工作树的属性；而已发布的 stable 不可变，
它改了什么，事后再也写不进去。

## Standing 多了第三类

skill 的 `Standing` 一直是二分：`plumb doctor` 会抓的，和没有任何机器会拦的。
这一条两边都不属于——它有机器强制，但强制者是发布链路。把它记进第一类，
恰恰就是那一节明令禁止的那种虚假声称。
