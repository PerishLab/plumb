# 迁移到 Plumb v0.29.0

## 治下仓库无需做任何事

编进二进制的配置仍是永久地板。一个从不同步 depot 座位的仓库，行为与 v0.28.0 下
完全相同，两条 depot 法对它都不出声。什么时候升级都行。

## 同步换来什么，代价是什么

`plumb depot sync` 把当前通道版本写进 `~/.plumb/depot/`，此后这个仓库的 lane 模板
与 Plumb 的法条来自那个座位，而不是来自二进制。**收益**是两者中任何一个的改动不必
等一次 Plumb 发布就能到你这里。**代价**是你从此持有一个版本，并且有两条法看着它。

`depot.roots-published` 只在记录着配置 roots 的那个仓库里出声，今天只有 Plumb 自己。
`depot.schema-supported` 在任何地方都出声：当持有的版本声明的下界高于运行中的二进制
时它拒绝 —— 这是 depot 在说「这份配置是给一个你还没装的 Plumb 写的」。修法是升级
Plumb，**永远不是去改座位**。

读取是本地的、永不取网，所以落后的座位是安静的而不是吵闹的。**存在却读不出的座位是
blind**，因为地板不该悄悄盖过一个有人打算使用的座位。

`PLUMB_DEPOT_SEAT` 把加载器指向别处，那是用来调试一份候选配置的，不是用来持有一份的。

## `plumb changelog` 改读 depot

它报告一个版本的说明席位是否被占，并列出席位里有什么。空席位以非零退出。它不再读
`docs/CHANGELOG`，治下仓库也不再需要一个 changelog 目录来满足任何法条。

## 发布说明在发布之后写，不在之前

编译一次发布不再校验说明，所以 `release compile` 不会因为说明缺失或超预算而停下。
等版本成为分发事实之后再写，写进 `.tmp/<product>/changelog/v<版本>/{en,zh}/`，然后
跑 `plumb depot changelog --version v<版本>`。发布动作会校验预算、上传、并清空暂存
座位；`--keep` 保留它，而用 `--from` 指定的来源**永不删除**。

说明日后可以改写，这正是要点：一个版本发出去之后才发现的坑，属于那一版的说明。

## 这个版本之前写下的封印仍带着 changelog 证明

它们照旧被读取。新的封印不再携带。下游仓库不需要为此改动任何东西。

## plumb 这个依赖可以落后于 stable latest

`deps.first-party-stable-latest` 不再因为一个仓库依赖的 Plumb 比线上 stable 旧而
拒绝它。一个 Plumb 根本读不出来的依赖仍然拒绝。如果你原先是靠钉版本来让那条规则
闭嘴的，现在不需要了。
