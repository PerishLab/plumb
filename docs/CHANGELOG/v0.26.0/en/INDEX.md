# Plumb v0.26.0

Seven cuts, all of them the same shape: a place where the mechanism trusted
something it had not measured.

## A release judges against a datum it recorded, not a registry it asks

The dependency law requires a first-party lock to resolve to the live stable
latest, and `plumb doctor` asked the registry at the moment it ran. A release
therefore froze its generator and then let the outside world move the verdict
underneath it: Plumb ships, and every dependent line goes red without a byte of
the product changing.

`plumb stable prepare` now records the answers the line will judge against — one
per first-party line the rule consults — as the line's first commit, under
`.plumb/releases/<version>/datum.toml`. On that line `doctor` reads the record;
off it, `main` keeps tracking live latest, because drift detection is still its
job and reproducibility is the line's. A release line carrying no datum is out
of true.

The seat under `.plumb` is Plumb's own, so source projection excludes it exactly
as it excludes `docs/CHANGELOG`; cutting a line does not invalidate a document
seal. `freeze` accepts the datum commit without cherry-pick provenance because
it proves itself: one known leaf that decodes for the line it names.

## A source seat holds nothing Git does not track

A document seal projects the index, and nothing asked what else sat in the seat.
A file left untracked simply did not exist, so the recorded seal stood for a tree
the working seat no longer was, and `doctor` stayed green up to the commit that
made the difference visible to somebody else.

A declared source seat holding an untracked leaf is now out of true, and
`plumb document` proposes nothing for that seat rather than handing over a seal
it cannot mean. Git's own ignore rules decide what counts, so the answer is
`git add` or `.gitignore` — both of which say something.

## One attachment is one object, and a projection never skips

Per-package bookkeeping shipped a broken pair: a macro crate reached the registry
and the library that requires it exactly did not, so the published crate was
reachable from nothing. One attachment declared two packages where there is only
one unit — a proc-macro must be its own crate because the language says so, and
the two live and die together.

An object is now one attachment. Every package it declares contributes to one
input hash, carries one version, and ships together, so there is no per-package
version to hold back and no pin table to derive.

Projection never skips. The skip rested on independent per-object versions, a
premise withdrawn while the skip stayed; with a published identity that carries
the version, not shipping is a hole in the sequence no later release can fill.
The input hash survives as evidence of what moved and decides nothing.

## The input digest measures what Git recorded

That digest read bytes from the working seat, so a release measured whatever lay
on the runner's disk rather than the candidate it was told to build. It now
covers each leaf's path, mode, and recorded object id: the answer moves when a
change is recorded and stays put when the seat is merely dirty.

## A watch ends when the run graph does

A run reporting success while its job list was empty read as finished, and so did
a run reporting success while one of its jobs had failed. Both are how a release
comes back green and publishes nothing. The verdict now comes from the graph, and
it is a plain function of the task list.

Two refusals also stopped speaking in riddles. A forge error names the operation
Plumb was performing when it arrived; `head out of date`, which Forgejo says to
any head it dislikes, names the commit the pull actually stands at.

## Plumb manages the numbers it must honour

How many packages an attachment may declare was governed by nothing, and the
forge image every rendered lane runs in was a constant somebody edited by hand.
Both live in Plumb's rules directory now. Widening a width is a change to Plumb,
which is the point: a product cannot grant itself a shape by declaring one.

Permitted is not the same fact as exercised, so they are two tables. A
declaration above the width Plumb has actually released is noted, never refused —
the gap between them is the only thing that can say a path has never been run.

## A late packport is refused before it collides

Packport reads as tidying and gets left for later, and later the next line is cut
over commits `main` has never seen. `prepare` and `freeze` now refuse while the
last stable point is a commit `origin/main` does not hold, and name the packport
that would settle it. The evidence is a tag and a `merge-base`, so the check
reaches nothing.

## This release is generated by its own beta

A release is generated by canonical stable Plumb, and canonical stable is the
version that still holds the skip. Left alone, v0.26.0 would have been shipped by
the defect it removes: `crates/macro`, `packages/`, `charts/` and `apps/` did not
move this cycle, so the macro crate, the module, the chart and the image would
each have been judged unchanged and left unpublished at this version.

So stable v0.26.0 is generated by the published exact beta `v0.26.0-beta.3`
standing at the same commit — a bounded contract that names one branch and one
beta, records that provenance in the seal, and comes out again in the release
that follows. The v0.20.0 self-hosting recovery it replaces, along with the
dispatch surface that named a workflow this repository no longer renders, is
gone.
