# Plumb v0.27.0

十二刀。大多数在拿掉同一样东西：一句**立在机制旁边、而不是从机制身上取来**的说法 ——
一份关于某个命令做什么的第二文档，一个没人量过的常数，一个在摘要唾手可得时却被接受的名字。

## 干跑走的就是它将要走的那条路

`--dry-run` 印的是一份**另写的文档**，手写在它声称要描述的代码旁边。两份文本必然漂移，
而且两个方向都实测到了：`plumb land` 的计划里写着一个客户端从不发送的查询，而
`plumb stable freeze` 印两行、实做六步 —— 第六步是 `git tag` 并推送。**一个预览从未提及
的不可逆动作**，出现在发布走到不可逆之前唯一的那次审查里。

挡住「只走一条路」的，是预览没法知道它没做过的事：分支停在哪个 commit、这条线到底存不存在。
占位符因此而生，第二份文本也因此而生。**但这个障碍是自己设的 —— 读不是变更。** 干跑现在
做完所有读、只跳过写，于是在每个写动作将要发生的那一刻，它知道真实运行知道的一切。
`prepare` 会**解析**分支到底存不存在，而不是把两种结果都描述一遍；`freeze` 印的是它将要
打 tag 的那个真实 commit，不是 `<head>`。

每个变更都作为**一个步骤**声明，而那个步骤的第一个参数就是描述它的句子 —— 于是「一个到达
远端却没有一行描述它的写动作」在代码里写不出来。读不到它需要的东西时，预览现在**拒绝**；
从前它会对着一条根本不存在的分支，自信地印出冻结它的计划。

## npm 的证据是那个 tarball，不是那个名字

注册表回答「这个版本存在」时，模块适配器就跳过发布 —— 而那只证明**有东西**以那个身份发过。
发布之后它取回 `dist.shasum` 然后**丢掉**，只看命令有没有退出零。于是 npm 这条道对一次发布
能作出的最强宣称，就是「有这么个名字」—— 比 cargo、S3、oci、chart 都弱，也比同一次发布里
随行的 changelog 弱。

npm 能不能做得更好，此前**未知**，所以什么都没做。现在知道了，而且是量出来的：从 v0.26.0
新检出、按 lockfile 安装、stamp、pack，**逐字节复现出已发布的那个 tarball**。所以强校验成立。
`carried` 改读 `dist.integrity`（sha512，npm 客户端自己校验的那个值），并在**两处**比对：
发布前，判断立在那儿的版本是不是这次投影；发布后，让取回的摘要被读而不是被丢。任一处不符
即 `published module drift` —— oci 与 chart 早已在用的那个拒绝。

路上浮出一件事：第一次比对**没对上**，唯一的差别是 `package.json` 的键顺序。`stamp` 解析进
一个会排序的 map，于是清单顺手被字典序化了。**这里的可复现性靠的正是它，而且是无意中靠上的。**

## 介质要等发布真的立住了才投影

在投影 cargo / npm / oci / chart 之前，那道门读的是**本机磁盘上的 capsule**，只比里面的版本号。
capsule 是上传计划，产生在任何东西被上传之前 —— 所以它证的是「这台机器编译过这个版本」，
不是「这次发布立在什么地方」。而介质是向全世界读得到的注册表宣告版本的。

在 lane 里，这道门本来就不是承重的：投影的 job 依赖封印的 job，次序早已保证了它。**门真正
有用的是没有次序管着的时候** —— 操作者手工收尾一次发布。它现在把 seal 从公网 authority
读回来比对摘要，复用 `plumb ship binary verify` 已有的那次 fetch。capsule 里本来就带着那个
URL 和摘要，所以没有任何 job 需要新学一个变量。它只查 seal 而非每个对象，且只对产品真正
声明了的介质开火。

## 每种附件共用一个上限

附件能声明多宽，原本是一张逐介质的表，而表里的数字就是「走到它面前的那些产品恰好需要多少」。
**按观测到的压力定出来的上限，是产品给自己发的许可，只是多绕了几步** —— 而那正是这个文件
自称要防止的事。`ceiling = 10` 是所有附件共用的一个数，表里只留偏离它的。

## agent 预算量它所描述的东西

`document.magnitude` 说：每种策略按目标与**证据体量**施加量级。architecture 按源叶子数、
brief 按源行数，各自在一个走廊里；而 agent 与 design 写死 320 —— 一个不量任何东西的数字，
出现在读者最先打开的那份文档上。**常数在两头都错**：这个仓库长大时它没动过，于是压力落在
句子上，而不是落在「值得说的事有几件」上；同时它允许一个十来个文件的仓库同样写 320 行，
那根本不叫防守。agent 与 design 现在共用 architecture 那条臂 —— 守卫在它原本什么都没防的
地方收紧，在仓库挣来的地方让开。

## packport 成为 rejoin

`packport` 不是一个词。它坐在 `backport` 该在的位置上，而 backport 也不是这个操作：backport
把修复带到更老的线上，这个是把冻结的发布线合回 main、让 stable commit 从 main 可达。**方向
相反，货物也不同** —— 一个运内容，这个只运可达性。`rejoin` 顺着生命周期读得通：prepare、
pick、freeze、rejoin。

旧词进退休词典 —— **这正是把一次改名变成机制的东西**：任何仍带着它的被跟踪字节即 out of true，
在这个仓库，也在下一次发布到达的每个仓库。冻结的 changelog 历史保留旧词，因为源投影排除
那个座位，而不可变的历史不是拿来订正的。

同时，一次冲突的 rejoin 现在有**一个被命名的解法**，而不是每次各判一回。

## 封印开口讲它发出去的那个镜像

输入台账覆盖了每一种声明过的附件，只差一个。`oci` 根本没有对象，于是那个回答「自上一个
stable 以来哪些介质动过」的封印，对镜像**只字未提** —— 一个恰好开在没人会去看的地方的洞。
镜像现在是一个对象：它的 `Containerfile`，加上 `[release.depends]` 添的边；而当镜像包着本次
发布的归档时，版本也折进去，因为这样的镜像**随发布而动**，无论它的源码有多静止。

## 线和线上的点是两种对象

Plumb 在 `freeze` 里打 stable 的点，却把 exact 的点留给了手 —— 开一个 beta 的既定做法是
`git tag` 加 `git push`。**把这件事做对的机器早就有了** —— 带注释、幂等、拒绝移动一个已经
立住的点 —— 而它只有一个调用者。

给 exact 点补一个动词，把一道更老的缝顶了出来:**动词族是按「谁在跑」组织的，而它们实现的
模型是按「作用于什么对象」组织的**，于是 `stable` 一族同时持有线和线上的一个点。而线永远是
stable 的，点不是。

所以把对象分开。`plumb stable` 开线、摘 commit、冻结、合回 main，**不碰任何点**；
`plumb release stamp` 把一个版本名钉在它所指那条线的线头上，`plumb release retract` 撤掉一个，
**两种通道都管** —— 因为点就是「tag 意味着什么」，而 tag 正是发布那一段的起点。

`freeze` 不再打点，于是它原本由构造保证的那条不变式，被搬到一个查得出来的地方重新说了一遍:
**stable 派发在它的点尚未立在线头上时拒绝。** 一次 stable 发布现在是**先声明、后运行**，
而声明是明说出来的一步。那句裸 `git tag` 从流程里消失；`retract` 也不再只认 stable ——
exact 点可以被造它的那个动词撤掉，并从 authority 读它自己那条通道。

## 更小的几件真事

Debian 包把 semver 字符串**原样**写进 dpkg 的 `Version` 字段。dpkg 把 `-` 读作 upstream 与
revision 的分隔符，且空 revision 排在有 revision 之前，于是预发布版本宣称自己比它前面那个
正式版还新。现在只有第一个 `-` 变成波浪号。这件事今天咬不到任何人 —— 这条发布路径上没有
apt 仓库，安装脚本也从不碰那个 `.deb` —— 但一个已发布的产物不该带着「谁读谁错」的宣称。

落地的 commit 把自己的标题说了两遍，一次作为 subject，一次作为正文第一行，因为标题取 `%s`
而正文取 `%B`。这条线上每一个提交都带着它。

`doctor` 会点名那些版本与运行中二进制不一致的、已安装的 brief，无论它在哪里运行。这是**观察
而非判决**：操作者的座位不是仓库的事，一个为真的仓库在一份过期 brief 旁边仍然为真。

stable 指针在那次「必须等它先动才跑得起来」的排练之前推进；而生成 v0.26.0 的自举，在它自举
出来的那次发布已经自己站住之后，撤除了。
