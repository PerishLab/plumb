# Plumb v0.20.0

## Every adaptor is absorbed

`ship` carried `binary` alone while the other five media were declared and
refused. All six now answer: `binary`, `site`, `cargo`, `oci`, `chart`, and
`npm`. The refusal arm is gone because nothing is left to refuse.

`cargo` took the two deeds that `plumb release registry` held, so the object
that keeps the truth cycle no longer projects. `site` left the top level and
answers under `ship`. `oci`, `chart`, and `npm` are new: each carries a real
projection onto a real registry.

## A projection cannot outrun its seal

Every publishing deed now reads the compiled capsule and refuses one that seals
another version. Publication is therefore the single irreversible point in a
release, and one question answers the whole of it: a version with no published
seal has projected nothing, anywhere.

That property was not true while `registry` sat outside `ship`. A standalone
Cargo lane could publish crates with no capsule in sight, so "did this version
reach any medium" could only be answered by enumerating media and hoping the
list was complete. It is now answered by one seal probe.

Deeds that only prepare stay outside the rule and mutate nothing beyond the
working tree: `cargo rehearse`, `oci build`, `chart package`, `npm pack`.

## A stable release has a removable point

A stable line was a line and nothing else, so a prepared release had no handle
a withdrawal could take: the line is the permanent audit boundary and deleting
it destroys the record it exists to keep. `plumb stable freeze` now stamps
`vX.Y.Z` at the frozen head and refuses to move a point that already stands.

`plumb stable retract` removes that point. It reads the release authority first
and continues only on a plain absence. A served seal refuses, because the
version projected something; any other answer refuses too, because a
destructive act never runs on a reading it cannot trust. The choice is the
status code, never the prose.

What retraction removes is a name. The line stays standing and can be frozen
again.

## The carriers hold no workload

`Containerfile`, `charts/plumb`, and `packages/plumb` exist so the image,
chart, and module adaptors project a real medium rather than a described one.
They hold no responsibility, no lane consumes them, and each takes content when
content earns its place.

## JSR is retired and the site is Svelte

Nothing publishes to JSR, so no consumer can resolve a first-party package from
it. The registry, its protocol seat, and the radius dimension that read
`deno.lock` are gone; Cargo is the only lock radius reads. The site moved to
Svelte with that retirement, and the web shape moved with it: a web app carries
`@perish/design`, and views and components are `.svelte` files.
