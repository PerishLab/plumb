# Plumb v0.18.12

## 发布影响面

`plumb radius` 回答：对一个产品与一个候选版本，在给定的一组仓库根中，哪些已声明
席位当前解析低于它。它读取每个根的 `Cargo.lock`、`deno.lock` 与
`.runseal/deno.lock`，按 semver 与调用方指名的候选比较，**不需要注册表也不需要网络**。

读不到的根、不是目录的路径、以及不是版本的解析值，都各自带原因报为 blind，
而不是被算作"当前"。workspace 链接不是被消费的注册表版本，予以排除。

求值器不携带任何域词汇，也不读取私有控制面状态，因此由交付协调面提供那组根、
由 Plumb 提供判定。与 `precommit` 一样，它是一个操作而非 Doctor 规则，不产生 finding。

## 诚实的发布线切割

`plumb stable prepare` 过去即使分支已存在且未移动，也报告"已从 base 准备"。
现在：已存在且正处于 base 上的线报为 held；已存在但处于另一提交的线**拒绝**——
发布线是冻结的审计边界，prepare 不移动它。任一侧提交读不到时拒绝，而不是拿空值比较。
